# 在线 RL 环境模拟：Exploration-Exploitation Tradeoff 实验报告

**日期**: 2026-06-01 | **实验环境**: CPU (Simulation), PyTorch 2.8.0 | **脚本**: `src/simulate_ee_tradeoff.py`

---

## 1. 实验动机

推荐系统中的强化学习策略面临经典的 exploration-exploitation 权衡：

- **Exploitation (利用)**: 推荐已知用户喜欢的内容 → 短期 CTR 高，但导致回声室效应和用户疲劳
- **Exploration (探索)**: 推荐新颖/多样化内容 → 短期 CTR 可能下降，但发现新兴趣、提升长期留存

前序实验中 (Phase 3-4)，离线 CQL 训练的策略在 5% 数据上崩塌到 100% `exploit_similar`；修复后 (co-occurrence embeddings) 策略恢复了多样性，但由于离线数据的限制，无法真正评估探索的长期价值。

本实验构建**在线 RL 模拟环境**，使用合成用户模型系统性地评估不同探索参数下的 exploitation-exploration 权衡，验证 idea.md §4.2 中"短期 CTR 略降但长期累积奖励反超"的核心假设。

## 2. 实验设计

### 2.1 模拟环境架构

```
SimulatedUser (偏好向量、周期性购买、新颖度偏好)
       ↕  反馈 (click/purchase/dwell/skip)
OnlineSimulator (policy → action → strategy → item retrieval)
       ↕  动作 + 状态
POMDPPolicy (同一 src/rl/ 的策略网络，随机初始化, 未经训练)
   + MemoryManager (短期缓冲 + FAISS 长期存储)
   + RewardFunction (多组件奖励，与 src/rl/reward.py 一致)
```

### 2.2 模拟用户模型

| 属性 | 分布 | 说明 |
|------|------|------|
| 偏好品类 | 每用户 2–4 个 (Uniform) | 用户真正喜欢的品类 |
| 厌恶品类 | 每用户 0–2 个 | 绝对不感兴趣的品类 |
| 品牌忠诚度 | Beta(2,1), 2–8 个品牌 | 对特定品牌的偏好权重 |
| 价格敏感度 | Normal(0.5, 0.2) | 0=不敏感, 1=高度敏感 |
| 新颖度寻求 | Beta(2, 3) | 0=纯利用型, 1=纯探索型 |
| 周期性购买 | 30% 用户, 周期 7/14/21/30/60/90 天 | 消耗品定期复购模式 |
| 兴趣漂移率 | Normal(0.02, 0.01) | 每次交互后偏好迁移概率 |
| 疲劳率 | Normal(0.05, 0.02) | 重复曝光后的兴趣衰减 |

### 2.3 模拟物品池

| 参数 | 值 |
|------|-----|
| 物品数 | 2,000 |
| 品类数 | 20 |
| 品牌数 | 50 |
| Embedding 维度 | 128 (品类原型 + 噪声) |
| 质量分布 | Beta(2, 3), [0.05, 1.0] |

### 2.4 反馈模型

用户对推荐列表的响应基于以下因素:
- **品类匹配**: 偏好品类 0.8, 中性 0.3, 厌恶 0.05
- **品牌忠诚**: 品牌权重 × 0.7 + 0.3
- **价格匹配**: 距中位价格的归一化偏差
- **疲劳衰减**: exp(-疲劳率 × 曝光次数)
- **新颖度增益**: 探索动作 + 非偏好品类时 1.0 + 0.5 × 新颖度寻求
- **周期性增益**: 当周期性品类"到期"时 boost ×2.0

点击/购买概率由 softmax 选择 + sigmoid 阈值门控决定。

### 2.5 探索参数扫描配置

共 **28 组**配置, 覆盖 4 个维度:

| 维度 | 扫描值 | 配置数 |
|------|--------|--------|
| 固定 ε (fixed) | 0.0, 0.02, 0.05, 0.1, 0.15, 0.2, 0.3, 0.5 | 8 |
| 不确定性自适应 ε (adaptive) | base ∈ {0.02, 0.05, 0.1} × max ∈ {0.3, 0.5, 0.7} | 9 |
| 探索奖励权重 (expl bonus) | 0.0, 0.05, 0.15, 0.3, 0.5 | 5 |
| 固定 ε × 探索奖励 (交叉) | ε ∈ {0.1, 0.3} × bonus ∈ {0.05, 0.2, 0.5} | 6 |

### 2.6 评估指标

| 指标 | 含义 | 类别 |
|------|------|------|
| Total Reward | 所有用户×所有步数的累积奖励总和 | 长期价值 |
| Mean Step Reward | 每步平均奖励 | 综合效率 |
| Click Rate | 交互中获得点击的比例 | 短期效果 |
| Purchase Rate | 交互中产生购买的比例 | 短期效果 |
| Exploration Action Rate | 选择 `is_exploration=True` 动作的比例 | 探索行为 |
| Action Entropy | 16 动作的 Shannon 熵 | 动作多样性 |
| Unique Actions Used | 至少使用过一次的动作种类数 (最多 16) | 动作覆盖 |
| New Categories / User | 每个用户平均发现的新品类数 | 长期多样性 |

### 2.7 实验规模

| 参数 | 值 |
|------|-----|
| 模拟用户数 | 50 |
| 每用户交互步数 | 50 |
| 总交互量 | 2,500 steps × 28 configs = 70,000 |
| 策略网络 | POMDPPolicy (随机初始化, 未训练) |
| 运行时间 | ~173s (CPU, 6.2s/config) |

> **设计选择**: 策略网络使用随机初始化而非 BC 预热启动，以公平比较各探索参数在"从零开始在线学习"场景下的效果。这模拟了真实部署中无历史日志的冷启动场景。


**观察**:
- ε=0 是**全局最差配置**: 仅 5 个动作被使用，总奖励最低
- ε=0.15 达到**固定 ε 的峰值**: 总奖励 33,949 (vs ε=0 的 30,123)
- ε>0.15 后奖励下降: 过度随机探索干扰了有效利用
- 点击率在 ε=0.15 处最高 (.838)，随后单调下降

| Click Rate | .838 | .840 (+0.2%) |
| Purchase Rate | .144 | .154 (+6.9%) |
| Action Entropy | **1.59** | **2.14** (+35%) |

**关键发现**: 自适应 ε 在总奖励上略低 (‑2.1%)，但动作熵高出 35%，意味着策略分布更均匀、更不易崩塌到单一动作。在非稳态环境（用户偏好漂移）中，这种多样性可能带来更大的长期优势。

**观察**:
- Bonus=0.15 达到**最优平衡**: 总奖励最高，点击率最高

## 4. 核心洞察

### 4.1 纯利用是最差策略

Pure Exploit (ε=0) 在所有 28 个配置中排名接近垫底。原因:
1. **策略未训练** (随机初始化权重): 无探索时，策略只能贪婪选择随机 Q 值最高的动作
2. **Q 值偏差固化**: 早期随机选择的动作获得正反馈后，Q 值被推高，形成正反馈循环
3. **动作空间崩塌**: 仅使用 5/16 个动作，错失了其他可能更有价值的策略
4. **新品类发现少**: 16.1 vs 19.2 (少了 16%)

### 4.2 关键反直觉发现 (idea.md §4.2 核心假设)

| 假设 | 验证结果 |
|------|----------|
| "纯利用短期 CTR 更高" | **否** — 纯利用点击率最低 (.453 vs .864) |
| "探索牺牲短期 CTR" | **否** — 适度探索同时提升短期 CTR (+91%) |
| "探索与利用存在零和权衡" | **部分否定** — 最优配置在短期 AND 长期都更好 |
| "自适应 ε 优于固定 ε" | **定性优于**: 动作熵高 35%, 更抗崩塌 |

**对原假设的修正**: 在"从零开始在线学习"场景中，探索不是奢侈品而是**必需品**。没有探索，策略甚至无法发现哪些动作是好的利用目标。因此短期 CTR 与长期奖励不是零和的——适度探索**同时**改善两者。

### 4.3 倒U型曲线确认

```
Total Reward
    ↑
35k ┤               ● (ε=0.15)
    ┤            ╱         ╲
33k ┤         ╱               ╲
    ┤      ╱                     ╲
31k ┤   ╱                           ╲
    ┤● (ε=0)                            ● (ε=0.5)
29k ┤
    └───┬────┬────┬────┬────┬────┬───→ ε
       0   0.1  0.15  0.2  0.3  0.5
```

ε 过小 → 探索不足 → 崩塌到次优策略
ε 过大 → 过度随机 → 无法累积有效的 Q 学习信号
ε ≈ 0.1–0.15 → 最优平衡

### 4.4 对真实系统的启示

1. **永远不要用 ε=0 部署 RL 推荐系统** — 即使 BC 预热启动后，保留小量探索 (ε ≥ 0.05) 是必要的安全网
2. **探索奖励需要仔细校准** — bonus=0.15 是 sweet spot，超过 0.3 开始产生负面效果
3. **不确定性自适应 ε 更稳健** — 虽总奖励略低 (-2%)，但动作熵显著更高 (+35%)，在非稳态环境中有优势
4. **冷启动场景下探索更加关键** — 本实验用随机初始化策略模拟了最坏情况，结果表明探索可带来 14.7% 的改进

## 5. 与前序实验的关联

### 5.1 与 Phase 3 (策略崩塌) 的联系

Phase 3 中 CQL 离线训练的策略崩塌到 100% `exploit_similar`。本实验在在线设置中复现了类似模式: ε=0 时仅 5 个动作被使用。**共同机制**: 缺乏探索导致 Q 函数过早收敛到次优局部最优。

差异: Phase 3 的 BC 标签全部相同（"最佳 action"在 5% 数据下无区分度），而本模拟中反馈是有区分度的——即使如此，ε=0 仍然崩塌，因为策略没有机会发现更好的动作。

### 5.2 与 Phase 4 (消融) 的联系

Phase 4 中 `fixed_epsilon=0.1` 的 action 分布为 37.4% `explore_trending_global`。本实验中最优固定 ε=0.15 也展示出良好的 action 多样性 (14/16 actions)。一致的结论: **固定非零 ε 已能显著提升策略健康度**。

### 5.3 局限与展望

1. **合成数据的局限**: 模拟用户的反馈机制是简化模型，无法完全捕捉真实用户行为的复杂性 (社会影响、从众效应、季节性宏观趋势等)
2. **无 BC 预热启动**: 本实验用随机初始化策略模拟冷启动，真实部署会在 P5 日志数据上做 BC 预热启动后再在线微调
3. **下一步**: 在服务器上用 100% 真实 Beauty 数据训练 BC 策略，再在在线环境中做 ε/exploration_bonus 的 A/B 调优

## 6. 结论

1. **纯利用 (ε=0) 是最差策略** — 总奖励 30,123，比最优配置低 14.7%。策略崩塌到仅 5 个动作，新品类发现少 16%。

2. **适度探索 (ε=0.1–0.15, exploration_bonus=0.15–0.2) 是最优配置** — 总奖励 34,546，同时提升短期 CTR (.864) 和长期多样性 (19.2 新品类)。

3. **不确定性自适应 ε 提供更好的动作多样性** — 动作熵 2.14 vs 固定 ε 的 1.59 (+35%)，适合非稳态环境。

4. **探索奖励权重需校准** — bonus=0.15 最优，超过 0.3 后出现递减，因为奖励信号被 bonus 扭曲。

5. **核心假设被修正**: 探索与利用在该设置下并非零和关系。适度探索**同时**提升短期和长期指标，因为它让策略在冷启动阶段就能发现高质量的动作-反馈映射。
